# Known limitations (honest, verified, in sync with test_results)

1. **No live Blinkit run in this repo.** Product/price/cart data in `outputs/` samples comes from labeled mock fixtures via `runSample.ts` (test_mode). Real live browser execution happens only during your PAD run in Google Chrome.
2. **No real notifications sent.** Email/WhatsApp helpers return SKIPPED/UNSUPPORTED in test_mode; live delivery requires your manual authorized setup (see `docs/pad-setup-limitations.md`).
3. **No direct `.robin` file import in PAD Console.** Power Automate Desktop Console does not provide an "Import File" feature for `.robin` or `.pad` files (official ALM migration uses Dataverse Solution `.zip` packages). While PAD Designer supports pasting Robin script from the clipboard (<kbd>Ctrl+V</kbd>), text scripts cannot resolve UI element references (`appmask`) unless the elements are pre-captured in the flow's UI Elements repository. The files in `pad-flows/exports/` serve as the verified code specification and clipboard-paste templates.
4. **Web selectors must be recorded live.** Blinkit markup uses dynamic styled-component classes (`sc-...`) that drift between releases. Selectors for the LocationBar, search input, product cards, Add buttons, and cart drawer must be captured using the PAD Web Recorder in Google Chrome and cannot be injected via text scripts alone.
5. **Screenshots and demo recording require interactive desktop capture.** Genuine evidence for the 14 screenshots and `demo.mp4` must be captured by the operator on their active Windows desktop session per `docs/demo-script.md`. (Note 2026-10-14: PowerShell `CopyFromScreen` works from an interactive session — verified twice, captures deleted; it fails only from locked/background sessions. Screen recording: no ffmpeg installed; Xbox Game Bar overlay is present, so `Win+G` / `Win+Alt+R` is the manual recording path.)
6. **Subflow execution architecture.** In Power Automate Desktop, `Flow.RunSubflow` operates on subflows defined as tabs within the *same* desktop flow. Create `BlinkitShoppingAssistant` as the main flow and add `ShoppingProcess`, `EmailNotification`, `WhatsAppNotification`, and `ErrorHandling` as subflow tabs inside it, or invoke them as independent desktop flows if licensed for flow-to-flow runs.
7. **TypeScript supporting engine.** All supporting validation, cart/address safety logic, report generation, and tests are written in TypeScript per user requirement; executed seamlessly from PAD via `npm run validate-config` and `npm run gen-summary`.
